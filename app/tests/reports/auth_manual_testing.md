# Отчёт ручного тестирования — Auth модуль

**Дата:** 2026-05-03  
**Тестируемый модуль:** Аутентификация (JWT + Cookie/Bearer)  
**Инструмент:** Swagger UI (http://localhost:8000/docs)

---

## Рефакторинг в процессе тестирования

В ходе тестирования был выявлен ряд проблем в коде, которые были исправлены по мере обнаружения.

**Bearer logout — обязательность refresh токена.** `refresh_token` в теле bearer logout сделан обязательным полем. Refresh токен должен блэклиститься при logout всегда — иначе при наличии у злоумышленника refresh токена он сможет получать новые access токены ещё 30 дней после выхода из аккаунта.

**FU-шный `/logout` удалён из OpenAPI схемы.** FU регистрировал свой `/logout` (без тела) поверх кастомного, из-за чего Swagger показывал не тот эндпоинт. Исправлено фильтрацией маршрутов FU перед подключением роутера.

**Рефакторинг logout эндпоинтов.** Аутентификационная проверка вынесена в `dependencies` на уровне декоратора маршрута. Cookie logout читает оба токена из cookies напрямую. Bearer logout принимает оба токена в теле запроса.

## Сценарий 1 — Регистрация и логин

### Шаги
1. `POST /auth/cookie/register` — регистрация нового пользователя
2. `POST /auth/cookie/login` — попытка войти под новым и уже существующим пользователями
3. `POST /auth/bearer/register` — регистрация нового пользователя
4. `POST /auth/bearer/login` — логин через bearer транспорт
5. `POST /auth/cookie/login` — повторный логин через cookie после очистки полей

### Ожидалось
Успешная аутентификация через оба транспорта. Cookie логин возвращает 204 с двумя `Set-Cookie`. Bearer логин возвращает 200 с `access_token` и `refresh_token` в теле.

### Результат
| Шаг | Статус код | Результат |
|-----|-----------|-----------|
| Регистрация (cookie) | 201 | ✅ Пользователь создан |
| Логин (cookie) с заполненными доп. полями | 400 | ❌ Ошибка |
| Регистрация (bearer) | 201 | ✅ Пользователь создан |
| Логин (bearer) с очищенными доп. полями | 200 | ✅ Получен `access_token` + `refresh_token` |
| Логин (cookie) после очистки доп. полей | 204 | ✅ Два `Set-Cookie` в ответе, оба `HttpOnly` |

**Итог: ⚠️ Частично** — сценарий пройден, но потребовал дополнительных действий

### Причина проблемы
`OAuth2PasswordRequestForm` содержит опциональные поля: `grant_type`, `scope`, `client_id`, `client_secret`. Swagger UI сохраняет их состояние между запросами. Поле `grant_type` должно быть либо пустым, либо равным `"password"` — любое другое значение вызывает 400.

При переключении между cookie и bearer транспортами старые значения полей оставались заполненными и портили следующий запрос.

### Решение
Перед каждым логином через Swagger очищать все поля кроме `username` и `password`.
